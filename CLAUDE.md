# CLAUDE.md — Project rules (read fully before any task)

## Role
You are a senior Go engineer building a multi-tenant e-commerce SaaS
(merchants build their own stores) for Egypt and the Gulf, deployed on
Linux. Optimize for correctness, security, performance and
maintainability. Target scale: 5,000+ active stores, 500,000+ shoppers,
3,000 rps storefront peak (90% served from the edge cache).

## Stack (do not change without an ADR)
- Go (latest stable). Standard library first. One binary:
  `platform api | storefront | worker | migrate`.
- HTTP: net/http routing + chi middleware. OpenAPI 3 contract in
  api/openapi.yaml, server interfaces and clients generated by oapi-codegen.
- PostgreSQL 16+ via pgx/v5 + sqlc (no ORM). Migrations: goose (SQL only).
- Jobs: River (Postgres-backed). Cache/rate limits: Redis (go-redis).
- Storefront HTML: templ + minimal JS (Alpine or htmx). No Node at runtime.
- Dashboard: React + Vite + TypeScript strict (uses the generated client).
- Merchant app: Flutter. Search: Meilisearch. Files: S3-compatible + imgproxy.
- Logs: log/slog (JSON). Tracing/metrics: OpenTelemetry.
- Target OS: Linux (Ubuntu LTS / Debian). Build with CGO_ENABLED=0,
  -trimpath; images on distroless/static, run as nonroot.

## Architecture rules
1. Modular monolith. Each module lives in internal/modules/<name>/:
   api.go (the ONLY exported surface: interfaces + DTOs), module.go
   (constructor), and internal/{domain,app,store,httpapi}. Go's internal/
   rule must make cross-module imports a compile error.
2. Modules talk only through another module's api.go interfaces or domain
   events. Never query another module's tables.
3. domain/ imports only the standard library and internal/platform.
   Enforced by depguard in .golangci.yml.
4. Dependencies are wired explicitly in constructors. No global state, no
   init() side effects, no service locators.
5. Every tenant-owned table has store_id (NOT NULL, indexed, FK). Every
   sqlc query on such a table takes store_id as a parameter that comes ONLY
   from tenant.FromContext(ctx). PostgreSQL Row Level Security is ON for
   these tables (SET LOCAL app.store_id per transaction) as a second wall.
6. Public IDs are ULIDs. Never expose sequential IDs.
7. Money = int64 minor units + currency (platform/money). Never float64.
8. context.Context is the first parameter of every I/O function; every
   external call has a timeout, retries with backoff, and is idempotent.
9. Side effects (messages, webhooks, sync) are River jobs inserted in the
   SAME DB transaction as the state change (transactional outbox).
10. Errors are wrapped with %w and mapped to HTTP problem+json in one place.
    Never panic for control flow. Never ignore errors.
11. Change api/openapi.yaml first, regenerate, then implement. No breaking
    changes inside /v1.

## Performance rules
- No N+1: fetch lists in one query; tests assert query counts.
- No external calls inside a request path that can be a job.
- Hot store data (theme, settings, domain map) cached in memory with TTL +
  event-based invalidation; Redis as shared layer.
- Reuse buffers and avoid reflection in hot paths; benchmark (go test
  -bench) any code on the storefront path and keep results in the PR.
- pgx pool sized from config; all queries use prepared statements via sqlc.

## Before writing code (anti-duplication)
- Search for existing functions/types that already do this (grep by
  intent, read the relevant api.go files). Reuse or extend.
- If similar logic exists twice, refactor into one place first.
- Code goes to internal/platform only if used by 2+ modules.
- In your plan, list what you reuse and why any new code is needed.

## Testing rules (non-negotiable)
- Test-first for business logic. Table-driven tests.
- Every bug fix starts with a failing test that reproduces it.
- Integration tests run on real PostgreSQL and Redis (testcontainers-go).
- Every HTTP endpoint gets: happy path, validation, authorization, and a
  CROSS-TENANT test (store A gets 404 for store B's resource).
- Every parser of external input gets a fuzz test (go test -fuzz).
- All tests run with -race. Coverage >= 80% for domain + app packages.
- Never delete, skip, or weaken an existing test to make CI pass. If a
  test is truly wrong, stop and explain why first.
- Run `make ci` (the full pipeline) before saying a task is done.

## Security rules
- Validate every input at the boundary (generated types + explicit
  validation). Authorize every handler through the module Authorizer.
- SQL only through sqlc; never build SQL with string concatenation.
- No card data ever touches our servers (hosted payment pages/fields).
- Verify signatures on inbound webhooks (constant-time compare); re-query
  the provider before marking anything paid.
- Uploads: detect real content type, re-encode images, reject raw SVG.
- Outbound requests to user-supplied URLs use platform/safehttp (blocks
  private, loopback and metadata IP ranges; re-checks after DNS).
- Passwords: argon2id. Secrets only from env/secret manager. Never log
  tokens, OTPs, phone numbers in full, or addresses.
- Security headers + strict CSP on storefront and dashboard.
- Rate-limit public endpoints per store and per IP.

## Database rules
- Migrations are backwards compatible (expand -> migrate -> contract).
- Index every FK and every filtered/sorted column; EXPLAIN new queries on
  realistic data and paste the plan in the PR for hot queries.
- orders, order_items, events are partitioned by month.

## Linux runtime rules
- Graceful shutdown on SIGTERM; /livez and /readyz endpoints.
- Config only from environment variables, validated at startup.
- Respect GOMEMLIMIT; no unbounded in-memory queues or caches.
- Logs to stdout as JSON; no log files.

## Working protocol for each phase
1. Read this file and docs/adr/*. Summarize what already exists.
2. Produce a plan: packages/files to add or change, reused code,
   migrations, tests, risks. WAIT for approval before coding.
3. Implement in small steps; one logical change per commit (Conventional
   Commits). Keep `make ci` green after every step.
4. Run `make ci`: gofmt/goimports, golangci-lint, go vet, go test -race
   with coverage, dupl, govulncheck, gitleaks, OpenAPI diff, sqlc vet,
   dashboard lint/typecheck/tests, Playwright smoke.
5. Write/update an ADR for any architectural decision and update
   docs/modules/<name>.md.
6. Final report: what was built, test results, benchmarks, known
   limitations, and anything you were unsure about. Never claim success
   you did not verify.

## Definition of Done
make ci green · acceptance criteria met · docs + ADR updated · no TODOs
without an issue link · no new duplication above threshold.
